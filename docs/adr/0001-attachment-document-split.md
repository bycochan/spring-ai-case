# 附件体系与 RAG 文档体系分离

上传文件存在两条独立链路：RAG 文档上传（`/api/rag/upload`）将文件解析、分块、向量化后丢弃原始文件；公共附件上传（`/api/attachment/upload`）保留原始字节于内存、以 fileId 引用、不做任何向量化，专为多模态聊天服务。我们选择分离而非统一上传体系，因为两者生命周期与消费方式不同（检索用文本块 vs 直接回传多模态模型），且项目无数据库、全内存存储，统一抽象收益低。

## 后果

- 附件与文档的标识（fileId / documentId）不可互换，语义见 `CONTEXT.md`。
- 会话历史只存"文本 + fileIds"引用，不存 Media 负载；调模型前从附件表重建，历史回显走附件读取接口。附件失效（重启、被删）时消息降级为占位提示。
- 附件不清理，重启即清，与会话历史生命周期一致。
